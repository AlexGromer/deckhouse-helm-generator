# EPIC-06: спецификация

## 1. Термины

| Термин | Значение |
|---|---|
| Генерация (generation) | Один запуск `dhg generate` с данным набором флагов. Идентичность генерации — пара (`--output`, `--chart-name`) |
| Набор выходных файлов (output set) | Все файлы, которые генерация пишет под `--output`: chart'ы всех режимов, `values-*.yaml` (`--env-values`), `Makefile`/`.helmignore`/`ct.yaml` (`--monorepo`), каталоги `kustomize/` (`--kustomize`), `SYNTHESIS.md`, внешние файлы (`ExternalFiles`: `README.md`, `policy/*.rego`, `post-renderer/*`, `images.txt`, …). Пути — относительно `--output`, через `/` |
| base (база) | Набор выходных файлов прошлой генерации, байт в байт, после `--template-dir`. Хранится в снимке (snapshot) `.dhg/<chart-name>/base/` |
| ours (наше, текущее) | Файлы на диске под `--output` сейчас, с правками пользователя |
| theirs (их, новое) | Набор выходных файлов новой генерации |
| Отслеживаемый файл (tracked) | Файл, путь которого есть в base |
| Пользовательский файл | Файл на диске, которого нет ни в base, ни в theirs. dhg его не трогает |
| Конфликт | Ours и theirs изменили одно и то же место относительно base по-разному |
| diff3 | Трёхстороннее слияние текстов по строкам (Khanna, Kuber, Pierce, «A Formal Investigation of Diff3», 2007) |
| Myers diff | Алгоритм кратчайшего редакционного скрипта O((N+M)·D) (E. Myers, «An O(ND) Difference Algorithm and Its Variations», 1986) |

## 2. Требования

**Снимок и состояние**

- **R1.** Каждый `dhg generate` без `--dry-run` и без `--no-state` записывает `<output>/.dhg/<chart-name>/state.json` и `<output>/.dhg/<chart-name>/base/<путь>.base` для каждого файла набора theirs. Содержимое base байт в байт равно записанному файлу theirs. Суффикс `.base` нужен, чтобы инструменты, рекурсивно ищущие `Chart.yaml`, `kustomization.yaml` или `*.yaml` (helm-docs, генераторы каталогов Argo CD, golden `findCharts`), не принимали копии за настоящие chart'ы.
- **R2.** `state.json` содержит: `formatVersion` (1), `dhgVersion`, `chartName`, `mode`, `options` (эффективные флаги, отличные от значений по умолчанию, по правилам R16), `files` (массив `{path, sha256, mode}`, отсортирован по `path`). Временных меток нет: два одинаковых запуска дают одинаковый `state.json`.
- **R3.** `.dhg/` всегда лежит в `--output`, вне любого chart'а. `helm package <output>/<chart>` его не видит, правка `.helmignore` не нужна.
- **R4.** Перед использованием base sha256 каждого файла base сверяется с `state.json`. При расхождении — ошибка `base snapshot .dhg/<name>/base/<path>.base was modified (sha256 mismatch); use --force or --base-dir`; на диск ничего не пишется.

**Защита от затирания (без `--update`)**

- **R5.** Если `state.json` для (`--output`, `--chart-name`) существует и хотя бы один отслеживаемый файл на диске отличается от base (изменён или удалён), `generate` без `--update` и без `--force` завершается с ошибкой (exit 1) и ничего не пишет. Сообщение перечисляет до 20 таких файлов и предлагает `--update` или `--force`.
- **R6.** Если `state.json` существует и правок нет, `generate` пишет theirs и удаляет отслеживаемые файлы, которых нет в theirs. Каталоги, ставшие пустыми, тоже удаляются, но только внутри `--output` и только если в них нет пользовательских файлов.
- **R7.** Если `state.json` нет, а каталоги chart'ов в `--output` уже существуют, поведение прежнее (перезапись, без удаления). В stderr печатается `Note: <output> has no .dhg state: manual edits cannot be detected; the snapshot is written now`.
- **R8.** `--force` перезаписывает theirs поверх правок и удаляет отслеживаемые файлы, которых нет в theirs. Пользовательские файлы не трогаются.

**Слияние (`--update`)**

- **R9.** `--update` требует существующий `state.json` для (`--output`, `--chart-name`). `--chart-name` можно не указывать, если в `<output>/.dhg/` ровно один каталог. Без состояния — ошибка с подсказкой `--base-dir` (R27).
- **R10.** Файлы классифицируются по таблице §4.1. Каждый класс даёт одно действие и одну строку в плане.
- **R11.** Файлы `values.yaml`, `values-*.yaml`, `Chart.yaml` и `*.yaml`/`*.yml` вне каталогов `templates/` и `crds/` сливаются структурно (§4.3). Остальные текстовые файлы — через diff3 (§4.2). Файл с байтом `0x00` считается бинарным: при изменении с обеих сторон это конфликт без слияния.
- **R12.** Текстовый конфликт записывается в файл маркерами стиля diff3 (§4.2). Файл помечается в `MERGE.md`.
- **R13.** Конфликт в YAML не ломает файл: остаётся значение ours, над ключом ставится комментарий `# dhg-conflict: <описание>`, запись попадает в `MERGE.md` с путём, base, ours и theirs.
- **R14.** После слияния base := theirs (весь набор новой генерации), даже если есть конфликты. `state.json` пишется последним, после всех файлов.
- **R15.** Всё слияние вычисляется в памяти до первой записи. Ошибка на этапе вычисления (неразбираемый YAML, сбой генерации) — exit 1, на диск ничего не пишется.
- **R16.** Сохранённые флаги (`options` в `state.json`) — это все флаги `generate`, кроме `output`, `config`, `dry-run`, `verbose`, `update`, `force`, `no-state`, `bump`, `base-dir`, `refresh-digests`, `offline`. Пути из флагов `file`, `template-dir`, `kubeconfig`, `ssh-key` и пути исполняемых файлов в `plugin` сохраняются относительно `--output`; абсолютные пути — как есть.
- **R17.** Порядок приоритета при `--update`: флаг командной строки > `--config`/`.dhg.yaml` > `options` из `state.json` > значение по умолчанию.
- **R18.** Если эффективный `--mode` отличается от сохранённого, `--update` завершается ошибкой `mode changed (separate -> umbrella): regeneration cannot merge a different layout; generate into a new directory or use --force`.
- **R19.** Если версия dhg отличается от `dhgVersion`, печатается `Note: chart was generated by dhg <old>, now <new>: template changes of the generator are merged as regular changes`.
- **R20.** Exit code: 0 — без конфликтов; 3 — записано, есть конфликты (в том числе неразрешённые с прошлого запуска, R22); 1 — ошибка, ничего не записано.
- **R21.** `MERGE.md` пишется в `<output>/MERGE.md` при наличии конфликтов. При чистом слиянии существующий `MERGE.md` удаляется, если его первая строка — `<!-- dhg merge report -->`.
- **R22.** Неразрешённые конфликты прошлых запусков ищутся в отслеживаемых файлах ours: строки, начинающиеся с `<<<<<<< ours:` или `>>>>>>> theirs:`, и комментарии, начинающиеся с `dhg-conflict:`. Каждая находка — конфликт класса `unresolved` (exit 3), файл при этом сливается как обычно.
- **R23.** Идемпотентность: повторный `--update` с теми же входом и флагами не меняет ни одного файла (mtime не меняется: неизменённые файлы не перезаписываются) и возвращает 0, если нет неразрешённых конфликтов (R22).
- **R24.** `--update --dry-run` ничего не пишет. В stdout — план (таблица §5.3) и unified diff ours → результат для каждого изменяемого файла. Exit code — как у настоящего запуска (0/3/1).
- **R25.** Файлы `--template-dir` входят в theirs после применения стратегии (`ApplyTemplateOverrides`). Особой обработки нет: правка каталога переопределений сливается как изменение генератора.

**Версия chart'а**

- **R26.** `--bump none|patch|minor|major` (по умолчанию `none`). Если итог слияния меняет хотя бы один файл chart'а, `version` в его `Chart.yaml` увеличивается от значения ours по SemVer 2.0. В umbrella при повышении версии подчарта повышается и `dependencies[].version` с тем же `name` в `Chart.yaml` родителя; сам родитель повышается, если изменился он или любой его подчарт. При `none` версия сливается как обычный ключ: правка пользователя сохраняется, `--chart-version` в командной строке меняет theirs.

**Bootstrap**

- **R27.** `--update --base-dir <dir>` берёт base из каталога `<dir>`: та же раскладка, что у `--output`, например старая ревизия, выгруженная через `git worktree add`. `state.json` не нужен. Флаги — только из командной строки и конфига. После успешного слияния пишется `.dhg/<name>/`.

**dhg diff**

- **R28.** `dhg diff <dir1> <dir2>` выводит unified diff через Myers (3 строки контекста, заголовки `@@ -a,b +c,d @@`). Новый флаг `--exit-code`: exit 1 при наличии различий. Без флага — 0, как сейчас.
- **R29.** `dhg diff` пропускает каталог `.dhg/` в обоих деревьях.

## 3. Входы

| Источник | Факт | Правило |
|---|---|---|
| Набор theirs (в памяти, задача 01) | Содержимое и режим доступа (`0644`/`0755`) каждого файла | Режим `0755` у файлов `*.sh`, как в `WriteChart` |
| `<output>/.dhg/<name>/state.json` | Сохранённые флаги, версия dhg, режим, sha256 base | R2, R4, R16 |
| `<output>/.dhg/<name>/base/**/*.base` | Содержимое base | Байты; путь в наборе — без суффикса `.base` |
| Диск под `<output>` (ours) | Содержимое отслеживаемых файлов и файлов theirs | Читаются только пути из base ∪ theirs; остальное не сканируется |
| `--base-dir` | base для bootstrap | R27 |

## 4. Выходы

### 4.1. Классификация файлов

B, O, T — содержимое в base, на диске и в theirs; `—` — файла нет.

| B | O | T | Условие | Действие | Класс в плане |
|---|---|---|---|---|---|
| — | — | есть | | записать T | `added` |
| — | есть | есть | O = T | ничего | `unchanged` |
| — | есть | есть | O ≠ T | слить с пустой base (обычно конфликт add/add) | `merged` / `conflict` |
| есть | — | есть | T = B | не восстанавливать (удаление пользователем уважается) | `kept-deleted` |
| есть | — | есть | T ≠ B | не восстанавливать, конфликт modify/delete; новое содержимое — в `.dhg/<name>/base/<path>.base` | `conflict` |
| есть | есть | есть | O = B | записать T (если T ≠ O) | `updated` / `unchanged` |
| есть | есть | есть | T = B | оставить O | `kept` |
| есть | есть | есть | O = T | ничего | `unchanged` |
| есть | есть | есть | иначе | слить (§4.2 или §4.3) | `merged` / `conflict` |
| есть | есть | — | O = B | удалить | `removed` |
| есть | есть | — | O ≠ B | оставить O, конфликт modify/delete | `conflict` |
| есть | — | — | | ничего | — |
| — | есть | — | | пользовательский файл, не трогать | — |

### 4.2. Текстовый diff3 и маркеры

Конфликтный участок:

```
<<<<<<< ours: shop/templates/web-deployment.yaml (current)
        replicas: {{ .Values.replicas | default 2 }}
||||||| base: dhg 0.9.0
        replicas: {{ .Values.replicas }}
=======
        replicas: {{ .replicas }}
>>>>>>> theirs: dhg 0.10.0
```

Маркеры — 7 символов, как у git. Метка ours — `ours: <путь> (current)`, base — `base: dhg <dhgVersion из state.json>`, theirs — `theirs: dhg <текущая версия>`. Секция base выводится всегда (стиль diff3, не merge): по ней видно, что изменил каждый. Окончания строк сохраняются как в исходниках. Последняя строка без `\n` остаётся без `\n`, если обе стороны её так оставили.

### 4.3. Структурное слияние YAML

Правила (подробно — design.md §4.3):

- отображения (mapping) сливаются по ключам рекурсивно;
- скаляры и списки сравниваются семантически (после разбора), а не по тексту;
- список, все элементы которого во всех трёх версиях — отображения с уникальным скалярным `name`, сливается поэлементно по `name`; любой другой список атомарен;
- порядок ключей — как в ours; новые ключи из theirs добавляются в конец своего отображения в порядке theirs;
- комментарии ours сохраняются;
- конфликт (оба изменили одно значение по-разному, или один изменил, другой удалил) — остаётся значение ours и комментарий над ключом:

```yaml
    deployment:
      # dhg-conflict: generator changed this value from 3 to 4; your value 5 is kept (see MERGE.md)
      replicas: 5
```

Если ours удалил ключ, а theirs его изменил, ключ не восстанавливается. Конфликт тогда записывается только в `MERGE.md`: комментировать нечего.

### 4.4. `MERGE.md`

```markdown
<!-- dhg merge report -->
# Повторная генерация: конфликты

Генерация `shop` (dhg 0.9.0 → 0.10.0), режим umbrella. Base обновлена до новой генерации.
Разрешите конфликты и закоммитьте; следующий `dhg generate --update` проверит, что маркеров не осталось.

## Значения YAML

| Файл | Путь | База | Ваше | Новая генерация | Решение |
|---|---|---|---|---|---|
| shop/values.yaml | web-app.deployment.replicas | 3 | 5 | 4 | оставлено ваше значение |

## Текстовые конфликты (маркеры в файле)

- shop/charts/web-app/templates/web-deployment.yaml — 1 участок

## Изменено с одной стороны, удалено с другой

| Файл | Ваше | Генератор | Где новая версия |
|---|---|---|---|
| shop/templates/extra.yaml | удалён | изменил | .dhg/shop/base/shop/templates/extra.yaml.base |

## Переформатированные файлы

- shop/values.yaml — записан из разобранного YAML: пустые строки и отступы списков нормализованы
```

Значения в таблице — JSON в одну строку, обрезанный до 120 символов с `…`.

## 5. Интерфейс

### 5.1. Новые флаги `dhg generate`

| Флаг | Тип, умолчание | Смысл |
|---|---|---|
| `--update` | bool, false | Трёхстороннее слияние с правками (R9–R25) |
| `--force` | bool, false | Перезаписать правки (R8). Несовместим с `--update` |
| `--no-state` | bool, false | Не писать `.dhg/` (R1). Несовместим с `--update` |
| `--bump` | `none\|patch\|minor\|major`, `none` | Политика версии (R26). Действует только с `--update` |
| `--base-dir` | path, "" | Bootstrap (R27). Только с `--update` |

`--output` по умолчанию `./chart`, как сейчас. С `--update` флаг `--chart-name` можно опустить (R9): проверка в `PreRunE` (`cmd/dhg/main.go`, «chart-name is required») ослабляется только для `--update`.

### 5.2. Ключи `.dhg.yaml`

Все новые флаги допустимы как ключи конфига (`applyConfigFile` проверяет ключи по именам флагов). Ключ `update: true` в конфиге допустим, но не рекомендуется: команда перестаёт быть безопасной по умолчанию.

### 5.3. План (`--update`, stdout)

```
Regenerating shop (umbrella) in ./charts
  updated       shop/charts/web-app/values.yaml
  merged        shop/values.yaml
  conflict      shop/charts/web-app/templates/web-deployment.yaml (1 hunk)
  removed       shop/charts/web-app/templates/webApp-configmap-web-app-config.yaml
  added         shop/charts/web-app/templates/webApp-hpa.yaml
  kept          shop/templates/NOTES.txt
Merged 14 files: 9 updated, 1 added, 1 removed, 2 merged, 1 kept; 1 conflict -> charts/MERGE.md
```

Строки `unchanged` печатаются только с `-v`.

### 5.4. Совместимость

- Без `.dhg/` и без новых флагов поведение `generate` прежнее (R7), плюс появляется каталог `.dhg/`.
- `--dry-run` без `--update` — прежнее поведение: печать chart'ов, без чтения состояния.
- `dhg migrate` не меняется: двусторонний отчёт о дрейфе остаётся отдельной командой.
- `--template-dir`, `--with`, `--plugin` — без изменений (R25).

## 6. Невыводимое

- Намерение пользователя при конфликте: dhg не выбирает сторону, кроме безопасного правила «YAML остаётся валидным, значение пользователя сохраняется» (R13).
- Перенос правки в переименованный файл: переименование выглядит как удаление + пользовательский файл; конфликт modify/delete попадает в `MERGE.md`.
- Причина изменения theirs (вход или новая версия dhg): видна только версия (R19).

## 7. Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| `values.yaml` ours не разбирается как YAML | Структурное слияние невозможно → текстовый diff3 по R11; если и он конфликтует — маркеры (YAML станет невалидным), запись в `MERGE.md` с пометкой «файл не был валидным YAML» |
| Многодокументный YAML (`---`) вне `templates/` | Текстовый diff3 |
| Два файла theirs с одним путём (две генерации в одном `--output` с пересечением путей) | Ошибка до записи: `path <p> is tracked by generation <other>` (проверка по всем `.dhg/*/state.json`) |
| Отслеживаемый путь стал каталогом (или наоборот) | Ошибка до записи с указанием пути |
| Прерывание (SIGINT) во время записи | Записанные файлы остаются, `state.json` старый. Следующий `--update` идемпотентно доводит слияние: для записанных файлов O = T |
| Права на файл изменены пользователем (например, `0600`) | Содержимое сливается, режим ours сохраняется; для новых файлов — режим theirs |
| CRLF у пользователя | Строки сравниваются вместе с `\r`; смена окончаний строк пользователем выглядит как правка каждой строки (тот же результат дал бы git без `autocrlf`) |
| Удалён весь chart группы (сервис ушёл из входа) | Все его отслеживаемые файлы — `removed` (если не менялись), пустые каталоги удаляются (R6) |

## 8. Критерии приёмки эпика

- **AC1** (R1–R3): после `dhg generate -f tests/integration/fixtures/simple-app -o out --chart-name app` есть `out/.dhg/app/state.json` и `out/.dhg/app/base/app/values.yaml.base`, байт в байт равный `out/app/values.yaml`; в `out/.dhg` нет ни одного файла с именем `Chart.yaml`. `helm package out/app` не включает `.dhg`.
- **AC2** (R5, R8): после правки `out/app/values.yaml` повторный `generate` без флагов — exit 1, файл не изменён; с `--force` — файл равен новой генерации.
- **AC3** (R6): после удаления `configmap.yaml` из входа и повторного `generate` (без правок) файла `out/app/templates/webApp-configmap-web-app-config.yaml` нет; `helm template out/app` проходит.
- **AC4** (R9–R14, R17, R25; golden): сценарий задачи 09 во всех четырёх режимах — правка `replicas` 3→5 пользователем и смена образа `nginx:1.25`→`nginx:1.27` во входе дают рендер с `replicas: 5` и `image: nginx:1.27`; пользовательский шаблон `extra-configmap.yaml` сохраняется; `helm lint --strict` проходит.
