## Проблема

Пользователь генерирует chart, правит его (values, шаблоны, добавляет свои файлы) и коммитит в GitOps-репозиторий. Когда меняется вход (манифесты, кластер, образ), повторный `dhg generate` в тот же каталог:

1. **Молча затирает ручные правки.** `generator.WriteChart` (`pkg/generator/generator.go:93`) перезаписывает каждый файл через `os.WriteFile`, не сравнивая с диском. Проверено 2026-10-07 на `tests/integration/fixtures/simple-app`: строка `# my edit`, добавленная в `app/templates/webApp-deployment.yaml`, после повторной генерации пропала.
2. **Оставляет устаревшие файлы.** `WriteChart` ничего не удаляет. В том же эксперименте после удаления `configmap.yaml` из входа шаблон `app/templates/webApp-configmap-web-app-config.yaml` остался на диске, а ключ `services.webApp.configMaps` из `values.yaml` пропал. Шаблон начинается с `{{- $cm := $svc.configMaps.webAppConfig -}}`, а Go `text/template` (его использует Helm) на таком входе падает: `nil pointer evaluating interface {}.webAppConfig`. Ошибку воспроизвели на `text/template` с `missingkey=zero`. Запуском Helm не проверяли: в окружении нет helm. Итог: повторная генерация в существующий каталог даёт chart, который не рендерится.
3. **Нечем сравнить.** `dhg diff` (`cmd/dhg/main.go:1279`, `printUnifiedDiff` на строке 1399) сравнивает строки по номеру позиции, а не через LCS (longest common subsequence — наибольшая общая подпоследовательность). Одна вставленная строка помечает изменёнными все строки после неё. Exit code всегда 0. `dhg migrate` (`generator.DetectDrift`, `pkg/generator/migration.go:48`) сравнивает только два состояния, «было» и «стало». Он не отличает правку пользователя от изменения генератора.

Генерация детерминирована: два прогона `examples/05-full-stack` в режиме umbrella с `--include-schema --include-tests --with policies,istio,flux --env-values --kustomize` дали побайтно одинаковые 60 файлов (`diff -r`, 2026-10-07). В коде генерации нет `time.Now` и случайных значений. Поэтому трёхстороннее слияние (three-way merge) здесь применимо: если вход не изменился, новая генерация совпадает со снимком прошлой.

**О ADR-016.** ADR-016 (Deferred) говорит о слиянии *нескольких входных источников* (`merger.go`, `file-wins`). Фраза «без three-way merge в v1» в нём относится к конфликтам между источниками. Этот эпик решает другую задачу: слияние *выходного* chart'а с правками пользователя. Статус ADR-016 не меняется, решения эпика оформляются новыми ADR.

## Цель и результат

Повторная генерация переносит изменения входа в chart и сохраняет правки пользователя. Конфликтующие изменения видны, а не теряются.

```bash
dhg generate -f ./manifests -o ./charts --chart-name shop --mode umbrella   # 1-я генерация: chart + .dhg/shop/
vim charts/shop/values.yaml                                                # правки пользователя
git commit -am "tune replicas"
# ... манифесты изменились ...
dhg generate --update -o ./charts            # флаги берутся из .dhg/shop/state.json
# Merged 14 files: 9 updated, 1 added, 2 removed, 2 merged; 1 conflict -> charts/MERGE.md
echo $?                                      # 3 — есть конфликты, файлы записаны
```

Фрагмент `charts/MERGE.md`:

```markdown
| Файл | Путь | База | Сейчас (ваше) | Новая генерация | Решение |
|---|---|---|---|---|---|
| shop/values.yaml | web-app.deployment.replicas | 3 | 5 | 4 | оставлено ваше значение |
```

## Scope

- В scope:
  - снимок последней генерации (base) в `<output>/.dhg/<chart-name>/`;
  - трёхстороннее слияние на уровне файлов (добавлен, удалён, изменён), текстовый diff3 для шаблонов и прочих текстов, структурное слияние YAML для `values*.yaml`, `Chart.yaml` и YAML вне `templates/`;
  - конфликты: маркеры в шаблонах, аннотация `# dhg-conflict:` в YAML, отчёт `MERGE.md`, exit code 3;
  - удаление файлов, которые генератор больше не производит, если пользователь их не менял;
  - защита от затирания: `generate` без `--update` не перезаписывает изменённые файлы (нужен `--force`);
  - политика версии `Chart.yaml` (`--bump`), согласованная для umbrella;
  - все режимы (`universal`, `separate`, `library`, `umbrella`) и все дополнительные файлы (`--env-values`, `--monorepo`, `--kustomize`, `--post-renderer`, `--airgap-registry`, `SYNTHESIS.md`);
  - собственный движок Myers diff + diff3 (`pkg/merge`); исправление `dhg diff` на его основе.
- Вне scope:
  - слияние нескольких входных источников (ADR-016, другая задача);
  - восстановление base из истории git без `.dhg/`. Как разовый bootstrap есть `--base-dir`: каталог, в который пользователь сам выгрузил старую ревизию (задача 08);
  - семантическое слияние Go-шаблонов (AST): шаблон Helm — текст с вкраплениями YAML, а структурный разбор не даёт гарантий;
  - интерактивное разрешение конфликтов (как `git mergetool`): разрешение остаётся пользователю и его редактору;
  - слияние при смене режима (`--mode`) — меняется вся раскладка файлов; без `--force` это ошибка.
