# decisions

Здесь лежат файлы значимых решений `ADR-NNN-slug.md`. Остальные решения живут одной строкой в таблице ADR файла `ARCHITECTURE.md` (раздел 3).

## Когда нужен файл

Файл нужен, если верно хотя бы одно: есть два и более реальных варианта, решение трудно отменить, меняется формат сущности. Иначе хватает строки в таблице; ячейка Decision не длиннее 400 символов (N33).

## Как завести

1. Скопируй шаблон `/opt/claude-toolkit/templates/decisions/ADR-template.md` в `decisions/ADR-NNN-slug.md`, где NNN идёт следом за последним в таблице.
2. В front matter задай `id`, `date` (ISO), `status`, `decision-makers`.
3. Заполни разделы Context, Options, Decision, Consequences, Confirmation (N31). Подтверждение это команда, тест или правило линтера, а не слово «проверено».
4. Добавь итоговую строку в таблицу ADR (`ARCHITECTURE.md`, раздел 3) и строку в Change Log (раздел 6), где в колонке ADR стоит ссылка вида `[[ADR-NNN]]` (N11).

## Принятое решение не правят

Принятый ADR это история (N32). Менять в нём можно только ключи front matter `status` и `superseded_by`; пояснения дописывают датированной строкой под `## Amendments`. Замена решения это новый ADR с `supersedes`, а у старого статус `Superseded by` со ссылкой на новый.
